# Состояние работы по «Головоломкам Големов» (сохранено 2026-10-17)

Приложение: `Golems_Puzzles/` (статический сайт, без сборки).
Репо: `simplrobot_git`. Всё описанное ниже — уже в коде и проверено автотестами;
непроверенное глазами — в разделе «Осталось проверить».
Файл можно удалить из финальной поставки — это рабочие заметки.

## 1. Как запускать и проверять

| Команда | Что делает |
|---|---|
| `node tools/serve.mjs 8099` | локальный сервер → http://localhost:8099/ (у пользователя был запущен 8460) |
| `node tools/validate.mjs` | прогон эталонных решений по всем комнатам → ждём `60 passed, 0 failed` |
| `node tools/validate.mjs 4` | только 4-й этаж |
| `node tools/test-programs.mjs` | тесты парсера программ / Python-редактора → ждём `10 passed, 0 failed` |
| `node tools/build-levels.mjs` | ПЕРЕСОБИРАЕТ `js/data/levels.js` из `data/bg4_export.json` |
| `node tools/_tmp_lv.mjs 4.10` | дамп комнаты: токены по слоям, старт, боты, текущий сценарий, решение |
| `node tools/_tmp_run.mjs 4.8` | прогон решения без браузера: печатает кадры и события |

Разблокировать все комнаты в браузере: `window.BG4.Progress.setUnlockAll(true)`.

**Важно:** `js/data/levels.js` автогенерируемый — править руками нельзя, только
`tools/build-levels.mjs`. Логика комнат живёт в `js/data/scenarios.js` (`S['X.Y']`).

## 2. Что сделано в этой сессии

1. **4.7 (и 1.9) больше не пустой экран.** Причина: в цикле анимации сцены остался
   доступ к несуществующему `p.spin` (портал) → исключение каждый кадр → для комнат
   с порталами не рисовалось ничего. Теперь портал — синее полупрозрачное кольцо,
   которое плавно поднимается/опускается над клеткой (без вращения):
   `portalMat()/portalMesh()` + блок `portalAnims` в `js/scene.js`.
2. **4.8 — Цикл теперь отрабатывает правильно.** Синий Голем шагает «Вперёд» перед
   КАЖДОЙ нашей командой, в том числе внутри Цикла: новый план бота
   `{ kind: 'everyCommand', cmd: 'forward' }`. В `runStatement` добавлены хуки
   `ctx.beforeCommand/afterCommand`, причём бот ходит и перед проверкой условия
   «Если» (раньше хук висел только на «Удар» и цикл фактически ничего не делал).
   Каждый шаг бота получает отдельный кадр, поэтому видно: бот толкает бочку →
   игрок её разбивает → бот подходит → второй удар убивает бота.
   `S['4.8'] = { objective: defeat, bots: [{ kind: 'everyCommand', cmd: 'forward' }] }`.
3. **Условия атаки «в лоб» / «сбоку»** (`js/engine.js`):
   `addPending(..., dir)` и `resolveLine` пишут `w.kills[id].frontal`;
   `constraints.frontOnly` — 3.7 и 3.9; `constraints.flankOnly` — 3.8.
4. **4.4** — `requireObstacle: true`: без Бочки перед Големом программа не стартует
   («перед ним нет препятствия…»). В `tools/validate.mjs` добавлен `withReserve()` —
   автотест сам ставит жетон «из руки» на клетку перед Големом.
5. Ранее в этой же сессии: резервные жетоны (`reserve`, комната 4.4), стековые
   клетки, PNG-линии без 3D-линий, анимации push/crush/slash/shield, порталы,
   read-only Blockly для ботов, блоки игрока, инфо-блок уровня в 4 строки, цитата
   под полем, сворачиваемая панель бота.

Автотесты после всех правок: `60 passed, 0 failed` и `10 passed, 0 failed`.

## 4. СЛЕДУЮЩИЙ ШАГ: параметры для отдельных уровней (запрос пользователя)

Пользователь: «добавить возможность задавать для некоторых уровней определённые
параметры. Например, 4.10: бочка должна взрываться, если она не окажется в воде
после 1 команды. Я проверю потом и напишу, что нужно доделать на каждом уровне».

Как делать:
- Место для параметров — уже существующий `js/data/scenarios.js`: у каждой комнаты
  есть объект `S[id]`, в него добавляем необязательный блок `params: { ... }`.
- Движок читает `scenario.params` и включает «механики уровня» независимо от
  `objective`/`bots`. Похожие механизмы уже есть: `dynamics` (движущиеся бочки
  этажа 5), `aiTable`, `botGoal`, `requireObstacle`, `endless`.

**Сделано (4.10) — механизм `params` уже подключён к движку:**
- `S['4.10'] = { objective: { type: 'soakBarrel' }, params: { bombBarrel: { fuse: 2, radius: 1, damage: 4 } } }`.
- Бомба взрывается: (а) при ударе по СУХОЙ Бочке — сразу (`attackCell` → `explodeBarrel`),
  (б) после отведённого числа команд игрока, если Бочка всё ещё на суше (`tickBomb`
  вызывается ПОСЛЕ команды; `fuse: 1` = одна команда даётся, чтобы столкнуть Бочку в воду).
  Подробнее — раздел 4а, пункт 1 (там же итоговое правило 4.10).
- Взрыв: Бочка исчезает, событие `explode` (в сцене — вспышка + ударная волна + дым),
  урон `damage` всем големам в радиусе `radius` (4 = смертельно); прогон падает с
  сообщением «Бомба в Бочке взорвалась! Сначала столкните Бочку в воду.».
- Победа в 4.10 — ТОЛЬКО за Бочку, разрушенную В ВОДЕ (`w.soaked`): разрушить её на
  суше или просто столкнуть в воду — не победа.
- Побочно (по подсказке 4.10): плавающая Бочка больше не считается Препятствием и для
  игрока (как давно для ботов) — её можно добить/перейти по ней; и каждая ВЫПОЛНЕННАЯ
  команда получает отдельный кадр, пустые кадры не добавляются (виден каждый шаг).
- `checkStaticEnd` теперь возвращает и текст сообщения (раньше финал прогона мог быть
  без текста).

**Осталось:** ждём от пользователя список «уровень → что должно происходить».
Каждая новая механика = `params: { <имя>: { ...поля } }` + небольшой модуль в
`engine.js`; все эффекты — обычными событиями кадра, чтобы анимации работали без правок.

## 4а. Сессия 2: карты, описания этажей, финальные правила 4.10

1. **4.10 — итоговое правило (сделано).** Бочку нужно СНАЧАЛА столкнуть в воду, а потом
   разрушить. Взрыв — во всех остальных случаях:
   - удар по СУХОЙ Бочке — взрыв сразу (`attackCell`);
   - Бочку НЕ столкнули в воду за отведённое число команд — взрыв: `params.bombBarrel
     = { fuse: 1, ... }`, а `tickBomb` вызывается ПОСЛЕ каждой выполненной команды
     (`fuse` = сколько команд даётся, чтобы намочить Бочку; при `fuse: 1` взрыв уже
     после первой команды).
   - Бочка в воде НЕ взрывается (плавающая Бочка — «мокрая», `barrelIsDry` = false).
   - Победа — только за Бочку, разрушенную В ВОДЕ (`w.soaked`). Если её столкнули в воду,
     но не разрушили, уровень не пройден: финальное сообщение «Бочка плавает в воде,
     но не разрушена — доведите удар!».
2. **Карты: правила палитры и названия.** `Prog.allowedCommands/availableCounts` теперь
   строго по бонусам комнаты: если в сведениях «Разрешённые карты (кроме перемещений):
   нет», в палитре только перемещения. Для этажа 6 (`anyCards: true`, его выдаёт
   `build-levels.mjs`) — «любые» карты, как и написано в описании этажа.
   Переименования: «Влево» → «Поворот влево», «Вправо» → «Поворот вправо»,
   «Стоять» → «Стоять на месте» (в т.ч. блок Blockly), палитра «+ Если» → «+ Условие»,
   карточка условия подписана «Условие: Препятствие». Ключи PNG-картинок карт
   (`cards/Влево Красный.png` и т.п.) не тронуты — это имена файлов.
3. **Описания этажей отформатированы** (`js/data/floor-intros.js` + `renderFloorIntro`
   в `js/app.js`): абзацы (пустая строка), подзаголовки («# …», сейчас только
   «Небольшая справка:» на 6-м этаже), списки («- …» — например, перечень стартовых
   команд). Текст 6-го этажа привёл к оригиналу курса (в т.ч. «мы не будем теперь
   подсказывать число ходов и использование бонусных карт»).
4. **Python-редактор показывает мини-программу с заголовком** (`pythonHeader` в
   `js/programs.js`): `# === Программа Голема ===`, номер комнаты, строка «Задача: …»,
   `#` и только потом код. Строки с `#` парсер игнорирует, поэтому заголовок можно
   править/дописывать прямо в редакторе. Без опций `toPython` отдаёт «голый» код —
   на этом держатся тесты и сравнения.

## 5. Шпаргалка «что где править»

- данные комнат: `js/data/levels.js` (автогенерация из `data/bg4_export.json`);
  `МБ` во 2-м слое помечает голема как бота.
- логика комнаты: `js/data/scenarios.js` — `S['X.Y']` (objective, constraints, bots,
  dynamics, endless, requireObstacle, answer, params).
- движок: `js/engine.js` — кадры (`snapshot` + `events`), ходы/атаки (отложенный урон
  в `resolveLine`), цели и проверки, планы ботов, `params`.
- сцена и анимации: `js/scene.js` — события кадра: `push`, `break_barrel`, `hit`,
  `damage`, `killed`, `explode`, `vanish`, `portal`, `rotate`, `defend`, `crush`.
- интерфейс: `js/app.js`, `index.html`, `css/style.css`;
  редакторы: `js/editor-blockly.js`, `js/programs.js` (карты/Blockly/Python).
- прогресс: `js/progress.js` (localStorage, экспорт/импорт).
