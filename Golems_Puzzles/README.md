# Головоломки Големов (Golem Puzzles)

**Версия: 1.0.0.**

3D-игра-головоломка по программированию для детей. Игрок составляет программу для
Голема и проводит его через 70 комнат Школы Големов (7 этажей по 10 комнат) —
Школа Големов находится в Королевстве Кибертания.

Этаж 7 «Параллельные Големы» — собственная разработка игры (в курсе его нет):
в комнате **два** Голема игрока и **одна** Программа на двоих, у Синего повороты
зеркальные, победа — оба Голема на своих Целевых точках в один и тот же ход.

Основано на настольной игре **«Битва Големов»** (издательство СИМПЛРОБОТ,
<https://simplrobot.ru>) и курсе **«Головоломки Големов v4.0»**
(<https://simplrobot.ru/members/courses/bg4_golovolomki>).

## Как запустить

Сборка не нужна — это статический сайт (чистый HTML/CSS/JS + локальная Three.js r128).

**Вариант 1 — просто открыть файл**

Дважды щёлкните `index.html`. Игра работает и по `file://` (все данные и Three.js
включены в поставку, сетевые запросы не нужны). При таком запуске (и вообще без
перехода со страницы курса) включается **ДЕМО-режим** — первые два этажа;
полную версию можно открыть, добавив к адресу `?access=full`
(см. «Полная версия и ДЕМО-режим»).

**Вариант 2 — локальный сервер**

```bash
node tools/serve.mjs 8181       # затем откройте http://localhost:8181/
```

(подойдёт и любой другой статический сервер: `python -m http.server`, nginx и т. п.)

**Размещение на сервере / в nginx**

Скопируйте всю папку `Golems_Puzzles/` на сервер и отдайте её как статику:

```nginx
location /golems/ {
    root /var/www;
    index index.html;
    # Golems_Puzzles лежит в /var/www/golems
}
```

Доступно только статике: серверных зависимостей, баз данных и сборки нет.
Если игра открыта не со страницы курса, она сама включает **ДЕМО-режим**
(первые два этажа) — как это работает и как включить проверку на стороне
сервера, смотрите раздел «Полная версия и ДЕМО-режим» ниже.

## Игровой процесс

1. **Меню → этаж → комната.** Комнаты открываются последовательно: следующая
   доступна только после решения предыдущей; этажи — один за другим.
2. В комнате есть **3D-поле** (вращение мышью, зум колесом), задание, подсказка,
   цель и ограничение на число строк программы. Над полем — **сердечки с числом
   жизней** игрока и ботов, на клетках — **подсветка зон Атаки** цветом того Голема,
   который держит клетку под атакой. Слева снизу — кнопка вида
   **«🃏 Жетоны / 🧊 3D-фигурки»**.
3. Программу можно собирать в трёх режимах, переключаемых вкладками:
   - **Карты команд** — простой список команд;
   - **Блоки (Scratch)** — те же команды в виде блоков-пазлов;
   - **Python-код** — текстовый аналог: `forward()`, `left()`, `attack()`,
     `repeat(2):`, `if obstacle:` / `else:`, `while True:`.
   Все три режима работают с одной моделью программы, так что переключение
   между ними сохраняет программу (Python парсится обратно в модель).
   У каждого Голема (и игрока, и бота) **одна жизнь**: атака без Защиты выводит
   Голема из строя, а для игрока означает проигрыш комнаты.
4. **Запустить** — Голем выполняет программу, поле анимируется (движение,
   атаки, тонущие бочки, боты-противники). **Показать ответ** подставляет
   эталонное решение (звёзд будет меньше).
5. **Звёзды:** 1 — за решение; 2 — без подсказки/ответа; 3 — ещё и уложиться
   в лимит строк без потери здоровья. За первое прохождение комнаты даются монеты.
6. **Справка** (📖) состоит из четырёх вкладок: «Правила», «Команды и обозначения»
   (уменьшенные карты команд, жетоны, Големы), «Как играть» (со скриншотами
   игрового экрана) и «Настройки». Текст справки — `js/data/help.js`.

Прогресс хранится в `localStorage` браузера (ключ `bg4.progress.v1`) и
экспортируется/импортируется через «Настройки» (текст JSON) — удобно переносить
между устройствами или сбрасывать.

## Открыть все уровни (родительский режим)

В «Настройках» есть пункт **«🔓 Открыть все уровни (для родителей)»**. Он снимает
последовательную блокировку: все этажи и комнаты становятся доступны сразу.

- Чтобы **включить** режим, нужно ввести пароль родителя. По умолчанию: **`golem`**.
- Чтобы **выключить** (снова закрыть уровни), пароль не требуется — достаточно снять
  галочку.
- Пароль задаётся константой `PARENT_PASSWORD` в начале `js/app.js`. Поменяйте строку
  `const PARENT_PASSWORD = 'golem';` на свою.
- Пароль проверяется на стороне браузера (в исходнике страницы), это защита «от
  ребёнка», а не от злоумышленника. Флаг режима хранится в прогрессе
  (`unlockAll`) и сохраняется в экспорте/импорте.
- В ДЕМО-режиме родительский режим **не открывает** этажи 3–7 (сайт ограничивает
  доступ к ним независимо от прогресса). Для проверки полной версии используйте
  `?access=full` (см. ниже).

## Полная версия и ДЕМО-режим

Полная версия (все 7 этажей) выдаётся тем, кто пришёл на страницу игры со страницы
курса:

```
https://simplrobot.ru/members/courses/bg4_golovolomki/onlajnversia-golovolomok-*
```

(код после `onlajnversia-golovolomok-` любой). Во всех остальных случаях — **ДЕМО**:
этажи 1–2 играются полностью, этажи 3–7 **видны на главной, но не открываются**,
над сеткой этажей показывается плашка **«ДЕМО»** с текстом и ссылкой на курс/игру
«Битва Големов» (<https://simplrobot.ru/bitvagolemov4#courses>).

**Как это работает (клиентская проверка, `js/license.js`)**

- Проверяется `document.referrer` регулярками (см. начало `js/license.js`):
  полный адрес страницы курса или одно происхождение `https://simplrobot.ru/`.
- Результат **запоминается в `localStorage`** (ключ `bg4.license.full`), иначе
  полная версия «терялась» бы при перезагрузке страницы (после reload реферер
  пустой). То есть достаточно один раз прийти со страницы курса.
- Включить полную версию вручную (отладка, локальный запуск, двойной щелчок по
  `index.html`): добавьте к адресу `?access=full`; вернуть демо — `?access=demo`;
  из консоли браузера — `BG4_LICENSE.setFull(true)`.
- Сброс: очистите localStorage сайта (или `?access=demo`).

**Временная ссылка полного доступа.** Чтобы выдать кому-то полную версию на
время, не отправляя его на страницу курса, на сервере есть «дверь»
`https://invapi.online/golovolomki/go/<токен>` (длинная) или
`https://invapi.online/g/<код>` (короткая): пока ссылка жива, она ставит
cookie `bg4gt` и перебрасывает в игру; после срока и на любой чужой токен —
404.

Срок действия задаётся в конфиге nginx (`/data/nginx/user_conf.d/invapi.online.conf`,
время сервера — UTC):

```nginx
map $time_iso8601 $golems_link_live {
    default 0;
    "~^2026-10-(2[2-9]|3[01])" 1;   # до 31.10.2026 включительно
}
```

Срок задаётся двумя независимыми параметрами:

- **окно дат** в `map $golems_link_live` — до какого числа ссылка открывается
  (время сервера, UTC);
- **`Max-Age`** в `Set-Cookie` — сколько живёт cookie после перехода по ссылке
  (по умолчанию 7 дней; `86400` = сутки).

**Короткая ссылка.** Для отправки человеку удобнее вид `https://invapi.online/g/<код>`:
8 знаков из `abcdefghjkmnpqrstuvwxyz23456789` (без `0/o` и `1/l/i` — легко
продиктовать по телефону), код случайный (`31^8 ≈ 8,5·10^11` вариантов, перебор
бессмыслен). Короткая и длинная ссылки живут по одному и тому же окну дат, у
каждой свой `location`; `location ^~ /g/ { return 404; }` закрывает остальные
короткие адреса и нужен один раз.

### Пошагово: короткая ссылка до 31.10.2026

Цель примера: ссылка `https://invapi.online/g/<код>` работает до 31 октября,
cookie — сутки (чтобы доступ не висел после срока).

**1. Сгенерировать код и срок** (локально, в папке `Golems_Puzzles/`, нужен Node):

```bash
node tools/temp-link.mjs --short --until 2026-10-31 --max-age-days 1
```

Вывод (код, разумеется, будет свой):

```text
  действует: 2026-10-22 — 2026-10-31 включительно (10 дн., UTC)
  cookie bg4gt: 1 дн. с момента перехода по ссылке
  URL: https://invapi.online/g/abc23def

map $time_iso8601 $golems_link_live {
    default 0;
    "~^2026-10-(2[2-9]|3[01])" 1;
}

location = /g/abc23def {
    if ($golems_link_live = 0) { return 404; }
    add_header Cache-Control "no-store";
    add_header Set-Cookie "bg4gt=$golems_gate_secret; Path=/golovolomki/; Max-Age=86400; Secure; SameSite=Lax";
    return 302 /golovolomki/;
}

location ^~ /g/ {
    return 404;
}
```

**2. Сервер: бэкап конфига и что в нём сейчас**

```bash
ssh root@176.222.53.68
cp /data/nginx/user_conf.d/invapi.online.conf \
   /data/nginx/user_conf.d/invapi.online.conf.bak-$(date +%Y%m%d-%H%M%S)
grep -n 'golems_link_live\|location = /g\|Max-Age' /data/nginx/user_conf.d/invapi.online.conf
```

**3. Правка** (`nano /data/nginx/user_conf.d/invapi.online.conf`) — три места:

- **срок**: в `map $golems_link_live` заменить строку с датой на новую
  (например `"~^2026-10-(2[2-8])" 1;` → `"~^2026-10-(2[2-9]|3[01])" 1;`);
- **cookie**: `Max-Age=604800` → `Max-Age=86400` (в блоке короткой ссылки;
  если блоков два — в обоих);
- **код**: заменить код в `location = /g/<старый код> {` на новый. Если короткой
  ссылки ещё нет — вставить блок `location = /g/<код> { ... }` целиком (см.
  вывод выше) рядом с другими `location`, внутри server-блока с `listen 443 ssl`,
  и один раз добавить `location ^~ /g/ { return 404; }`.

**4. Проверить конфиг и перезагрузить**

```bash
docker exec 3x-ui-nginx-1 nginx -t && docker exec 3x-ui-nginx-1 nginx -s reload
```

Если `nginx -t` ругается — конфиг не применён, вернуть бэкап:
`cp /data/nginx/user_conf.d/invapi.online.conf.bak-<дата> /data/nginx/user_conf.d/invapi.online.conf`.

**5. Проверить снаружи**

```bash
K=https://invapi.online/g/<код>
curl -sSI $K | grep -iE 'HTTP/|location:|set-cookie:'                  # 302 + Max-Age=86400
curl -sS -o /dev/null -w '%{http_code}\n' https://invapi.online/g/deadbeef   # 404

curl -sS -c /tmp/jar -o /dev/null $K                                   # «переход» по ссылке
curl -sS -b /tmp/jar -o /dev/null -w '%{http_code}\n' \
  https://invapi.online/golovolomki/js/data/levels-full.js             # 200 — полная версия
curl -sS -o /dev/null -w '%{http_code}\n' \
  https://invapi.online/golovolomki/js/data/levels-full.js             # 403 — без cookie
rm -f /tmp/jar
```

**6. Отправить ссылку.** Открытие сразу включает полную версию (этажи 3–7);
коммитить ничего не нужно — конфиг живёт только на сервере.

### Длинная ссылка (прежний вид)

Шаги те же, отличается только вид ссылки: токен 32 символа и путь
`/golovolomki/go/<токен>`.

```bash
node tools/temp-link.mjs --until 2026-10-31 --max-age-days 1                    # новый токен
node tools/temp-link.mjs --until 2026-10-31 --max-age-days 1 --token <текущий>  # продлить
```

В конфиге — `location = /golovolomki/go/<токен>` и
`location ^~ /golovolomki/go/ { return 404; }`.

Ключи генератора: `--days N` (по умолчанию 7), `--until YYYY-MM-DD`,
`--from YYYY-MM-DD`, `--max-age-days N` (7), `--short` (короткий вид `/g/<8
знаков>`), `--code <код>` (свой код), `--token <16–64 символа>` (свой токен),
`--path <префикс>` (другой путь вместо `/g/`).

### Отзыв и продление

Код (или токен) — секрет: он есть только в конфиге на сервере, в репозиторий его
класть не нужно. Отозвать доступ раньше срока — поменять код в `location`
(старая ссылка сразу даст 404) или поставить в `map` дату в прошлом и
перезагрузить nginx. Продлить — тот же `location`, новое окно дат в `map`.

Cookie живёт отдельно от ссылки: если нужен жёсткий обрыв, ставьте маленький
`Max-Age` (например `3600` — час) и не отправляйте ссылку в последний день.

**Важное ограничение.** Реферер передаётся браузером, и при переходе на **другой
домен** его по умолчанию обрезают до origin (`strict-origin-when-cross-origin`), то
есть из `https://simplrobot.ru/members/.../onlajnversia-golovolomok-123` придёт
только `https://simplrobot.ru/`. Поэтому проверка сводится к правилу «пришёл со
`simplrobot.ru` — полная версия»: на странице курса (GetCourse) нельзя добавить
`<meta name="referrer" content="unsafe-url">`, чтобы к нам приходил полный адрес.
Проверка клиентская: её видно в исходниках и легко обойти.

**Серверная защита (nginx, как развёрнуто на сайте).** Referer, ведущий на
`simplrobot.ru`, есть только у запроса самой страницы игры (index.html); при
запросах остальных файлов (`js/...`) referer уже `invapi.online`. Поэтому nginx
вычисляет флаг на запросе страницы и **встраивает его прямо в HTML через SSI**:

```nginx
# Только пришедшие со страницы курса («полная версия»)
map $http_referer $golems_full {
    default 0;
    "~*^https?://simplrobot\.ru/members/courses/bg4_golovolomki/onlajnversia-golovolomok" 1;
}

location = /golovolomki {
    return 301 /golovolomki/;
}

location /golovolomki/ {
    alias /data/www/simplrobot/Golems_Puzzles/;
    index index.html;
    ssi on;                # встраивает флаг в index.html
    try_files $uri $uri/ /golovolomki/index.html;
    add_header Cache-Control "no-store";   # флаг зависит от Referer
}
```

А в `index.html` перед `<script src="js/license.js">` стоит врезка:

```html
<!--# if expr="$golems_full = 1" -->
<script>window.BG4_FORCE_FULL = true; window.BG4_GATE = "<!--# echo var="golems_gate" default="" -->";</script>
<!--# else -->
<script>window.BG4_FORCE_DEMO = true;</script>
<!--# endif -->
```

Так режим включается **до** отдачи js/license.js и его нельзя снять из браузера.
Локально (двойной щелчок по `index.html`) SSI не работает, врезка остаётся
комментарием, и режим определяет клиент (`js/license.js`). Актуальная версия
конфига — в `/data/nginx/user_conf.d/invapi.online.conf` на сервере.

**Блок T123 «HTML-код» на странице курса (Tilda/GetCourse).** Ссылку на игру
вставляйте с атрибутом `referrerpolicy="unsafe-url"` — тогда браузер передаст
полный адрес страницы курса в Referer, даже если платформа по умолчанию его
обрезает. Непубличный триггер в самой ссылке не нужен.

Кнопка (игра в новой вкладке):

```html
<a href="https://invapi.online/golovolomki/" referrerpolicy="unsafe-url"
   target="_blank" rel="noopener"
   style="display:inline-block;padding:14px 22px;border-radius:12px;
          background:#ffd76a;color:#1a1533;font-weight:700;text-decoration:none">
  ▶ Играть в «Головоломки Големов»
</a>
```

Игра прямо в уроке (iframe):

```html
<iframe src="https://invapi.online/golovolomki/" referrerpolicy="unsafe-url"
        style="width:100%;height:640px;border:0;border-radius:12px"
        allow="fullscreen" title="Головоломки Големов"></iframe>
```

Если платформа удаляет атрибут `referrerpolicy` при сохранении — в ДЕМО-плашке
игры строка диагностики покажет `referrer: (пусто)`; тогда напишите
сопровождающему игры — придумаем обход (например, промежуточная страница на
`invapi.online`, которую открывает `window.open` с собственным контекстом).

**Жёсткая защита: этажи 3–7 на сервере.** Комнаты и сценарии закрытых этажей
вырезаны в отдельные файлы `js/data/levels-full.js` и `js/data/scenarios-full.js`
(разрезание делает `tools/build-levels.mjs`). В ДЕМО эти файлы не запрашиваются
вовсе: `js/license.js` подключает их через `document.write` только при полном
доступе, поэтому данных закрытых этажей в браузере нет — их нельзя «открыть» ни
из консоли, ни из localStorage. nginx отдаёт защищённые файлы только с
cookie-ключом `bg4gt`, который выдаётся странице полного доступа при первом
заходе со страницы курса (значение ключа живёт в nginx-конфиге, SSI встраивает
его в HTML только в полной сборке). Без ключа прямой запрос файла даёт 403:

- голая ссылка (`invapi.online/golovolomki/`) — ДЕМО, данных этажей 3–7 нет;
- заход со страницы курса — полная версия; повторные заходы (закладка,
  перезагрузка) работают по cookie-ключу — страница снова открывается полной;
- из браузера перехитрить нельзя; ключ можно выудить из исходников полной
  страницы — это заслон от списывания, а не сейф.

Сырой экспорт курса `data/bg4_export.json` на сайте закрыт (404). Этаж 7 —
собственная разработка игры, его исходные данные лежат рядом в
`data/floor7-export.json` (тоже 404 на сайте). Проверки:
`node tools/validate.mjs` (70 комнат на настоящем движке) и
`node tools/test-split.mjs` (демо не протекает, полная сборка собирается).

Тесты логики доступа: `node tools/test-license.mjs` (24 проверки).

## Инструменты (tools/)

Требуется Node.js (запускать из папки `Golems_Puzzles/`):

| Скрипт | Назначение |
| --- | --- |
| `serve.mjs [port]` | Локальный статический сервер для проверки. |
| `build-levels.mjs` | `data/bg4_export.json` + `data/floor7-export.json` → `js/data/levels.js`, `js/data/levels-full.js`. |
| `validate.mjs [floor...]` | Прогоняет эталонное решение каждой комнаты через движок. **Все 70 комнат проходят.** |
| `test-programs.mjs` | Юнит-тесты модели программы (Python-парсинг, разбор решений). |
| `test-license.mjs` | Тесты логики «полная версия / ДЕМО» (referrer, localStorage, флаги). |
| `trace.mjs <room>` | Покадровый лог/трассировка комнаты (отладка). |
| `search.mjs` | Перебор программ игрока (использовался для ответов шахматного этажа). |
| `summarize.mjs`, `inspect-rot.mjs`, `dump-bot-programs.mjs`, `fetch-bot-images.mjs` | Вспомогательные (анализ курса/данных). |

Проверки:

```bash
node tools/validate.mjs        # все комнаты
node tools/test-programs.mjs   # модель программы
node tools/test-license.mjs    # полная версия / ДЕМО
```

## Модель правил (кратко)

- **Направление:** поворот 0 = Север (строка −1), 90 = Восток (столбец +1),
  180 = Юг (строка +1), 270 = Запад (столбец −1).
- **Обозначения клеток:** ВК/ВП/ВУТ — вода, КВ — камень, ПВ — портал, Л — лёд,
  Б — бочка, Ц — цель, ПЛ/УЛ — линии, ПРЖ — пружина; Големы К/С/З/Ж.
- **Лимит строк** считает только команды верхнего уровня (тела `Цикл`/`Если`
  в лимит не входят). `lineN` в исходных данных = лимита нет.
- **Боты** выполняют свою программу перед каждой командой игрока; урон и защита
  разрешаются в конце хода. Условие «Препятствие»: камни, бочки, вода, линии и
  роботы — препятствие; лёд, портал и цель — нет (плавающая бочка-мост для бота
  препятствием не является).

## Точность и допущения

- **Этажи 1–4** перенесены полностью и проверены симуляцией по эталонным решениям курса.
- **Этажи 5–6** частично аппроксимированы: программы ботов там в курсе даны
  картинками (блок-схемами) и воспроизведены в движке вручную. Динамика
  (пинг-понг/линия/цикл бочек), бесконечные циклы и «шахматные» боты
  воспроизведены по изображениям.
- Для нескольких комнат эталонный ответ курса не совпадает с движком (в исходном
  онлайн-задании срабатывает не всё, что нарисовано). Для них в
  `js/data/scenarios.js` заданы явные `answer`:
  - **4.1** — `Если <Препятствие>, то (Влево), Иначе (Защита) → Вперед`
  - **5.4** — `Вправо → Вперед → Влево → Вперед` (плюс лимит 4 строки)
  - **5.6** — `Вперед → Вперед → Вперед → Влево → Вперед → Вперед`
  - **5.9** — `Вперед → Вперед → Вправо → Вперед → Вперед`
  - **6.2–6.7, 6.9, 6.10** — ответы подобраны поиском под движок
    (6.1 и 6.8 используют ответы курса).
  Все 70 комнат проходят проверку `tools/validate.mjs`.

## Совместимость

Любой современный браузер с WebGL (Chrome, Edge, Firefox, Safari). Интернет не
требуется. Прогресс — локальный, на сервере ничего не хранится.

## Правовая информация

«Битва Големов», «Головоломки Големов» и материалы курса принадлежат
издательству СИМПЛРОБОТ (<https://simplrobot.ru>). Проект — некоммерческая
образовательная реализация; изображения и данные получены из открытых
материалов курса.
