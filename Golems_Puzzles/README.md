# Головоломки Големов (Golem Puzzles)

3D-игра-головоломка по программированию для детей. Игрок составляет программу для
Голема и проводит его через 60 комнат Школы Големов (6 этажей по 10 комнат).

Основано на настольной игре **«Битва Големов»** (издательство СИМПЛРОБОТ,
<https://simplrobot.ru>) и курсе **«Головоломки Големов v4.0»**
(<https://simplrobot.ru/members/courses/bg4_golovolomki>).

## Как запустить

Сборка не нужна — это статический сайт (чистый HTML/CSS/JS + локальная Three.js r128).

**Вариант 1 — просто открыть файл**

Дважды щёлкните `index.html`. Игра работает и по `file://` (все данные и Three.js
включены в поставку, сетевые запросы не нужны).

**Вариант 2 — локальный сервер**

```bash
node tools/serve.mjs 8181       # затем откройте http://localhost:8181/
```

(подойдёт и любой другой статический сервер: `python -m http.server`, nginx и т. п.)

**Размещение на сервере / в nginx**

Скопируйте всю папку `Golems_Puzzles/` на сервер и отдайте её как статику:

```nginx
location /golems/ {
    root /var/www;
    index index.html;
    # Golems_Puzzles лежит в /var/www/golems
}
```

## Игровой процесс

1. **Меню → этаж → комната.** Комнаты открываются последовательно: следующая
   доступна только после решения предыдущей; этажи — один за другим.
2. В комнате есть **3D-поле** (вращение мышью, зум колесом), задание, подсказка,
   цель и ограничение на число строк программы. Над полем — **сердечки с числом
   жизней** игрока и ботов, на клетках — **подсветка зон Атаки** цветом того Голема,
   который держит клетку под атакой. Слева снизу — кнопка вида
   **«🃏 Жетоны / 🧊 3D-фигурки»**.
3. Программу можно собирать в трёх режимах, переключаемых вкладками:
   - **Карты команд** — простой список команд;
   - **Блоки (Scratch)** — те же команды в виде блоков-пазлов;
   - **Python-код** — текстовый аналог: `forward()`, `left()`, `attack()`,
     `repeat(2):`, `if obstacle:` / `else:`, `while True:`.
   Все три режима работают с одной моделью программы, так что переключение
   между ними сохраняет программу (Python парсится обратно в модель).
   У каждого Голема (и игрока, и бота) **одна жизнь**: атака без Защиты выводит
   Голема из строя, а для игрока означает проигрыш комнаты.
4. **Запустить** — Голем выполняет программу, поле анимируется (движение,
   атаки, тонущие бочки, боты-противники). **Показать ответ** подставляет
   эталонное решение (звёзд будет меньше).
5. **Звёзды:** 1 — за решение; 2 — без подсказки/ответа; 3 — ещё и уложиться
   в лимит строк без потери здоровья. За первое прохождение комнаты даются монеты.
6. **Справка** (📖) состоит из четырёх вкладок: «Правила», «Команды и обозначения»
   (уменьшенные карты команд, жетоны, Големы), «Как играть» (со скриншотами
   игрового экрана) и «Настройки». Текст справки — `js/data/help.js`.

Прогресс хранится в `localStorage` браузера (ключ `bg4.progress.v1`) и
экспортируется/импортируется через «Настройки» (текст JSON) — удобно переносить
между устройствами или сбрасывать.

## Открыть все уровни (родительский режим)

В «Настройках» есть пункт **«🔓 Открыть все уровни (для родителей)»**. Он снимает
последовательную блокировку: все этажи и комнаты становятся доступны сразу.

- Чтобы **включить** режим, нужно ввести пароль родителя. По умолчанию: **`golem`**.
- Чтобы **выключить** (снова закрыть уровни), пароль не требуется — достаточно снять
  галочку.
- Пароль задаётся константой `PARENT_PASSWORD` в начале `js/app.js`. Поменяйте строку
  `const PARENT_PASSWORD = 'golem';` на свою.
- Пароль проверяется на стороне браузера (в исходнике страницы), это защита «от
  ребёнка», а не от злоумышленника. Флаг режима хранится в прогрессе
  (`unlockAll`) и сохраняется в экспорте/импорте.

## Управление

- Мышь: зажать ЛКМ и тянуть — поворот камеры; колесо — приближение/отдаление.
- Touch: свайп — поворот.

## Структура проекта

```
Golems_Puzzles/
  index.html              — разметка экранов (меню / карта / комната) и модалок
  css/style.css           — оформление (тёмная тема, карточки, редакторы, модалки)
  lib/three.min.js        — Three.js r128 (UMD, локальная копия)
  assets/img/*.png        — иконки/текстуры из исходного веб-редактора
  data/bg4_export.json    — сырые данные курса (источник истины, 60 комнат)
  js/
    data/levels.js        — window.BG4_LEVELS (сгенерировано из export)
    data/scenarios.js     — window.BG4.SCENARIOS (цели, боты, динамика, ответы)
    programs.js           — модель программы + режимы Карты/Scratch/Python
    engine.js             — детерминированный симулятор и правила
    scene.js              — 3D-вид (Three.js): поле и анимация кадров
    progress.js           — прогресс в localStorage, разблокировка, звёзды
    app.js                — UI, экраны, редактор, запуск
  tools/                  — служебные скрипты (см. ниже)
```

## Инструменты (tools/)

Требуется Node.js (запускать из папки `Golems_Puzzles/`):

| Скрипт | Назначение |
| --- | --- |
| `serve.mjs [port]` | Локальный статический сервер для проверки. |
| `build-levels.mjs` | `data/bg4_export.json` → `js/data/levels.js`. |
| `validate.mjs [floor...]` | Прогоняет эталонное решение каждой комнаты через движок. **Все 60 комнат проходят.** |
| `test-programs.mjs` | Юнит-тесты модели программы (Python-парсинг, разбор решений). |
| `trace.mjs <room>` | Покадровый лог/трассировка комнаты (отладка). |
| `search.mjs` | Перебор программ игрока (использовался для ответов шахматного этажа). |
| `summarize.mjs`, `inspect-rot.mjs`, `dump-bot-programs.mjs`, `fetch-bot-images.mjs` | Вспомогательные (анализ курса/данных). |

Проверки:

```bash
node tools/validate.mjs        # все комнаты
node tools/test-programs.mjs   # модель программы
```

## Модель правил (кратко)

- **Направление:** поворот 0 = Север (строка −1), 90 = Восток (столбец +1),
  180 = Юг (строка +1), 270 = Запад (столбец −1).
- **Обозначения клеток:** ВК/ВП/ВУТ — вода, КВ — стена, ПВ — портал, Л — лёд,
  Б — бочка, Ц — цель, ПЛ/УЛ — линии, ПРЖ — пружина; Големы К/С/З/Ж.
- **Лимит строк** считает только команды верхнего уровня (тела `Цикл`/`Если`
  в лимит не входят). `lineN` в исходных данных = лимита нет.
- **Боты** выполняют свою программу перед каждой командой игрока; урон и защита
  разрешаются в конце хода. Условие «Препятствие»: стены, бочки, вода, линии и
  роботы — препятствие; лёд, портал и цель — нет (плавающая бочка-мост для бота
  препятствием не является).

## Точность и допущения

- **Этажи 1–4** перенесены полностью и проверены симуляцией по эталонным решениям курса.
- **Этажи 5–6** частично аппроксимированы: программы ботов там в курсе даны
  картинками (блок-схемами) и воспроизведены в движке вручную. Динамика
  (пинг-понг/линия/цикл бочек), бесконечные циклы и «шахматные» боты
  воспроизведены по изображениям.
- Для нескольких комнат эталонный ответ курса не совпадает с движком (в исходном
  онлайн-задании срабатывает не всё, что нарисовано). Для них в
  `js/data/scenarios.js` заданы явные `answer`:
  - **4.1** — `Если <Препятствие>, то (Влево), Иначе (Защита) → Вперед`
  - **5.4** — `Вправо → Вперед → Влево → Вперед` (плюс лимит 4 строки)
  - **5.6** — `Вперед → Вперед → Вперед → Влево → Вперед → Вперед`
  - **5.9** — `Вперед → Вперед → Вправо → Вперед → Вперед`
  - **6.2–6.7, 6.9, 6.10** — ответы подобраны поиском под движок
    (6.1 и 6.8 используют ответы курса).
  Все 60 комнат проходят проверку `tools/validate.mjs`.

## Совместимость

Любой современный браузер с WebGL (Chrome, Edge, Firefox, Safari). Интернет не
требуется. Прогресс — локальный, на сервере ничего не хранится.
